# SeniorOS Visual Style

## Brand position

SeniorOS should look like a serious developer tool: calm, precise, inspectable, and modern. The visual system deliberately avoids cyberpunk scenery, 3D chrome, excessive glow, fake dashboards, and generic AI imagery.

## Color tokens

| Token | Hex | Use |
|---|---|---|
| Midnight | `#0B1220` | Primary dark surface |
| Surface | `#111827` | Secondary dark surface |
| Signal Blue | `#2F80FF` | Primary action / brand accent |
| Sky | `#6BB6FF` | Highlight / gradient pair |
| Slate | `#94A3B8` | Secondary text |
| Pass | `#22C55E` | Verified / proven |
| Risk | `#F59E0B` | Attention / elevated risk |
| Blocked | `#EF4444` | Failure / blocked state |
| Review | `#8B5CF6` | Review / analysis |

## Typography

Use **Inter** when available, otherwise the platform system sans stack. Use **JetBrains Mono** when available for commands and code; fall back to the system monospace stack. No font files are bundled.

## Logo rules

- Keep clear space around the mark equal to roughly one quarter of its width.
- Do not skew, rotate, add drop shadows, or place the mark inside arbitrary gradients.
- The blue gradient may only run from Sky to Signal Blue.
- On noisy backgrounds, use the official dark tile.

## README rules

- One hero.
- One explanatory infographic per major concept at most.
- Prefer real command output and architecture diagrams over decorative art.
- Animated assets must remain understandable with animation disabled.

## Voice

Precise, calm, direct and falsifiable. Avoid “magic”, “revolutionary”, “perfect”, and claims that exceed implemented capability.
